### FURPS+ таблица для MVP цифровизации депозитного направления

| Код | Требование | Комментарий |
|-----|------------|-------------|
| **F** | **Функциональные требования** |
| F1 | Клиент может подать заявку на депозит через сайт (ФИО + телефон) | Данные передаются в кол-центр для обратной связи |
| F2 | Клиент может подать заявку на депозит через интернет-банк (выбор счёта, суммы) с SMS-подтверждением | Требуется интеграция с СМС-шлюзом |
| F3 | Автоматический расчёт персонализированных ставок для клиентов интернет-банка | Интеграция с АБС для доступа к данным клиента |
| F4 | Хранение и управление ставками в АБС (вместо Excel) | Необходима доработка АБС с разделением прав доступа между отделами |
| F5 | Отправка уведомлений клиенту (SMS/email) на всех этапах процесса | Использование существующего СМС-шлюза |
| **U** | **Удобство использования** |
| U1 | Время отклика интерфейса < 500 мс | Оптимизация загрузки справочных данных |
| U2 | Соблюдение корпоративного дизайна (цвета, брендинг) | Единый стиль для сайта и интернет-банка |
| U3 | Простота формы заявки (не более 3 полей для сайта) | Уменьшение барьера входа для новых клиентов |
| **R** | **Надёжность** |
| R1 | Доступность 99.9% для интернет-банка | Требуется настройка отказоустойчивости между ЦОД |
| R2 | Защита передаваемых данных (TLS 1.2+) | Обязательно для передачи персональных данных |
| R3 | Резервное копирование новых данных (ставки, заявки) | Интеграция с существующей системой бэкапов АБС |
| **P** | **Производительность** |
| P1 | Обработка заявки в бэк-офисе < 5 мин | Автоматизация расчёта ставок сократит время |
| P2 | Поддержка 1000 одновременных сеансов в интернет-банке | Горизонтальное масштабирование frontend-серверов |
| P3 | Отклик API АБС < 1 сек | Ограничение вертикального масштабирования АБС |
| **S** | **Поддерживаемость** |
| S1 | Совместимость с MS SQL и Oracle | Использование существующих СУБД |
| S2 | Документация API для будущего расширения | Описание интеграционных точек |
| S3 | Логирование всех операций с заявками | Для аудита и отладки |
| **+R** | **Ограничения** |
| +R1 | Запрет прямой интеграции интернет-банка с АБС | Использовать промежуточный слой (API Gateway) |
| +R2 | Использование существующих технологий (Java/.NET) | Для минимизации обучения сотрудников |
| +R3 | Вертикальное масштабирование АБС | Архитектурное ограничение Oracle |
| +R4 | Обязательная идентификация новых клиентов в отделении | Требование регулятора |

**Архитектурно-значимые требования**:
1. **F4** + **+R1**: Перенос логики работы со ставками в АБС с промежуточным API-слоем для защиты от перегрузки.
2. **R1** + **P2**: Настройка кластеризации интернет-банка с балансировкой нагрузки между ЦОД.
3. **+R3** + **P3**: Оптимизация запросов к АБС (кеширование справочников) для компенсации ограничений масштабирования.

**Дополнительные требования**:
- **Мониторинг**: Внедрение Prometheus/Grafana для отслеживания нагрузки на АБС в реальном времени.
- **Тестирование**: Нагрузочное тестирование API перед запуском (с учётом прогнозируемого роста клиентов).
- **Безопасность**: Реализация механизма JWT для аутентификации между системами вместо прямого доступа к БД.
