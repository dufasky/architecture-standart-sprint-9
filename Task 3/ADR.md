### Функциональные требования

| № | Действующие лица/системы | Use Case | Описание |
|:-:|--------------------------|----------|-----------|
| 1 | Клиент, Сайт | Подача заявки на депозит через сайт | Клиент заполняет форму (ФИО, телефон), данные шифруются и передаются в кол-центр |

### Решение

**Диаграммы:**
1. `context_diagram.png` - Контекстная диаграмма C4 (основные системы и взаимодействия)
2. `container_diagram.png` - Диаграмма контейнеров с детализацией интернет-банка и АБС

**Ключевые компоненты:**
1. **API Gateway** (новый):
   - Промежуточный слой между интернет-банком и АБС
   - Реализован на .NET Core (совместимость с текущим стеком)
   - Кеширование справочных данных для ускорения работы

2. **API Gateway** (новый):
   - Промежуточный слой между партнерской системой колл-центра и АБС
   - Реализован на .NET Core (совместимость с текущим стеком)
   - Кеширование справочных данных для ускорения работы

3. **Модуль депозитов** (доработка):
   - Вынесение в отдельный компонент для потенциального масштабирования
   - Хранение депозитов в Oracle
   - Разграничение прав доступа между отделами
   - Интеграция с кредитным риском
   - Обработка запросов из ИБ/сайта идет через отдельные сервисы, Разгрузка АБС (АБС получает только синхронизированные данные)

4. **Сервис уведомлений**:
   - Объединяет СМС и email-оповещения
   - Использует существующий СМС-шлюз

5. **Модуль ставок** (доработка)
   - Вынесение в отдельный компонент для потенциального масштабирования
   - Хранение ставок в Oracle
   - Обработка запросов из ИБ/сайта идет через отдельные сервисы, Разгрузка АБС (АБС получает только синхронизированные данные)

6. **Брокер сообщений** (новый)
   - Асинхронное взаимодействие между сервисами (ABS, модуль депозитов и ставок)
   - Каждый сервис можно масштабировать независимо (модуль депозитов и ставок)
   - Kafka обеспечивает асинхронную обработку пиковых нагрузок






**Логика выбора технологий:**
- Минимизация изменений в АБС (Oracle PL/SQL)
- Использование .NET для новых компонентов (существующая экспертиза)
- API Gateway вместо прямой интеграции для защиты АБС

### Альтернативы

1. **Прямая интеграция интернет-банка с АБС**
   - *Плюсы:* Быстрее реализация
   - *Минусы:* Риск перегрузки АБС, нарушение требований безопасности

2. **Внедрение Kafka для асинхронной обработки**
   - *Плюсы:* Масштабируемость
   - *Минусы:* Несовместимость с текущей версией интернет-банка

**Риски:**
1. Перегрузка АБС при пиковых нагрузках
   - *Митигация:* Ограничение количества параллельных запросов через API Gateway

2. Задержки в расчете ставок
   - *Митигация:* Предварительный расчет базовых ставок

3. Недостаточная пропускная способность СМС-шлюза
   - *Митигация:* Добавление очереди сообщений в сервисе уведомлений
