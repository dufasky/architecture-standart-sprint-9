### Функциональные требования

| № | Действующие лица/системы | Use Case | Описание |
|:-:|--------------------------|----------|-----------|
| 1 | АБС, Кол-центр банка | Автоматическая синхронизация ставок | Ежедневное обновление ставок через API |
| 2 | АБС, Партнерский кол-центр | Выгрузка файла ставок | Генерация CSV-файла для SFTP-передачи |
| 3 | Сотрудник кол-центра, CRM | Консультация клиента | Отображение актуальных ставок в интерфейсе CRM |
| 4 | RateService, АБС | Расчет специальных ставок | Учет персональных условий клиента |

### Нефункциональные требования

| № | Требование |
|:-:|-----------|
| 1 | Обновление ставок не реже 1 раза в сутки |
| 2 | Защита передаваемых данных (TLS/SFTP) |
| 3 | Совместимость с форматом CSV для партнера |
| 4 | Время отклика API <500 мс |

### Решение

**Диаграммы:**
1. `context_rates.png` - Контекст передачи ставок
2. `container_rates.png` - Компоненты системы расчета ставок

**Ключевые изменения:**
1. **Новый сервис ExportService**:
   - Генерация CSV-файлов по расписанию
   - SFTP-выгрузка для партнера
   - Валидация формата данных

2. **Модуль ставок в CRM кол-центра**:
   - Кеширование ставок
   - История изменений
   - Интеграция с существующей CRM

**Обоснование:**
- Использование CSV/SFTP для партнера соответствует их ограничениям
- Единый RateService исключает расхождения данных
- Кеширование снижает нагрузку на АБС

### Альтернативы

1. **Прямой доступ к АБС из кол-центра**
   - *Плюсы:* Нет задержек в данных
   - *Минусы:* Нарушает изоляцию АБС, не решает проблему партнера

2. **Реализация API для партнера**
   - *Плюсы:* Единый механизм обмена
   - *Минусы:* Требует изменений у партнера, сроки не соответствуют MVP

**Риски:**
1. Расхождение данных между банковским и партнерским кол-центрами
   - *Митигация:* Ежедневная синхронизация + алерты при расхождениях

2. Перегрузка SFTP-сервера
   - *Митигация:* Очередь обработки файлов
